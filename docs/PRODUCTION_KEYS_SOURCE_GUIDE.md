## 2. If you would rather not add a card at all

Then you need an **always-on, publicly reachable HTTPS host** for the
SearXNG container from `infra/searxng/Dockerfile.prod`. Any of these works
because the package is a plain Dockerfile:

| Host | Card needed? | How to start it | Trade-off |
|------|--------------|-----------------|-----------|
| **Fly.io** (target platform) | yes (above) | `flyctl deploy -c infra/searxng/fly.toml.local` | most reliable fit; ~USD 5/mo |
| **Render** | yes, but free instance tier exists | New → Web Service → Dockerfile `infra/searxng/Dockerfile.prod` → env `SEARXNG_SECRET`, `SEARXNG_AUTH_TOKEN` | free instances spin down when idle |
| **Railway** | yes (trial credit) | New project → Deploy from GitHub → root `infra/searxng` | trial credit expires |
| **Hugging Face Spaces** (Docker) | **no** | create a free account → *New Space* → SDK **Docker** → push the image | free CPU spaces sleep after inactivity |
| Any **VPS** with Docker | yes | `docker build -f Dockerfile.prod -t searx . && docker run -e SEARXNG_SECRET=… -e SEARXNG_AUTH_TOKEN=… -p 8080:8080 searx` | you administer the box |

Whichever host you pick, three things are mandatory and are handled by the
same commands:

* a **public HTTPS URL** (no `http://localhost` — the backend rejects
  loopback URLs outside development),
* `SEARXNG_SECRET` and `SEARXNG_AUTH_TOKEN` injected as **runtime secrets**
  (never baked into the image, never committed),
* the container **must not start without** `SEARXNG_AUTH_TOKEN`
  (the shipped entrypoint already enforces this — fail closed).

Afterwards the only Vercel values that change are the three in §0.

## 3. Exact commands (copy-paste) once a host exists

Everything below is generated locally and piped straight into the secret
stores — **the values never appear on screen, in logs, or in Git**.

```powershell
# --- 3.1 generate the two Fly secrets (PowerShell, one line each) ---
$SEARXNG_SECRET = -join ((1..64) | ForEach-Object { '{0:x}' -f (Get-Random -Max 16) })
$SEARXNG_TOKEN  = -join ((1..64) | ForEach-Object { '{0:x}' -f (Get-Random -Max 16) })
# (bash equivalent: SEARXNG_SECRET=$(openssl rand -hex 32)  SEARXNG_AUTH_TOKEN=$(openssl rand -hex 32))

# --- 3.2 create the app, build, inject secrets, restart ---
cd "e:\Realestate gpt"
Copy-Item infra\searxng\fly.toml infra\searxng\fly.toml.local   # gitignored
# edit fly.toml.local: app = "<your-unique-app-name>"
flyctl apps create <your-unique-app-name>
flyctl deploy -c infra/searxng/fly.toml.local
flyctl secrets set -a <your-unique-app-name> "SEARXNG_SECRET=$SEARXNG_SECRET" "SEARXNG_AUTH_TOKEN=$SEARXNG_TOKEN"
flyctl apps restart -a <your-unique-app-name>

# --- 3.3 verify the instance (expect 200 / 401 / 200 + real results) ---
curl.exe -s -o NUL -w "%{http_code}`n" "https://<app>.fly.dev/healthz"                      # 200
curl.exe -s -o NUL -w "%{http_code}`n" "https://<app>.fly.dev/search?q=test&format=json"    # 401
curl.exe -s -H "Authorization: Bearer $SEARXNG_TOKEN" "https://<app>.fly.dev/search?q=2bhk+hyderabad&format=json" | ConvertFrom-Json | ForEach-Object { $_.results.Count }   # > 0

# --- 3.4 wire it into Vercel (existing project only) ---
vercel env add WEB_DISCOVERY_ENABLED production --force --value true --project realestate-gpt
vercel env add SEARXNG_BASE_URL production --force --value "https://<app>.fly.dev" --project realestate-gpt
$SEARXNG_TOKEN | vercel env add SEARXNG_AUTH_TOKEN production --sensitive --project realestate-gpt

# --- 3.5 redeploy ---
cd "e:\Realestate gpt"
vercel --prod
```

If you ever need the value again later, regenerate nothing: rotate it with a
fresh pair of commands and update both sides together.

## 4. Where every ALREADY-SET key came from (reference only — do not re-enter)

| Variable | Source of the value | Action |
|---|---|---|
| `MONGODB_URI` | MongoDB Atlas → **Database → Connect → Drivers** (cluster `…mongodb.net`) | none (SET) |
| `MONGODB_DATABASE` | Atlas database name, `realestate_gpt` | none (SET) |
| `SECRET_KEY` | generated at project setup (`openssl rand -hex 32`) | none (SET) |
| `GROQ_API_KEY` | https://console.groq.com → **API Keys** | none (SET) |
| `GROQ_MODEL` | `qwen/qwen3.8-27b` (verified in `docs/AI_MODEL_SELECTION.md`) | none (SET) |
| `LOCATION_PROVIDER` | `osm` — no account, no billing | none (SET) |
| `CORS_ORIGINS` | `https://realestate-gpt-inky.vercel.app` | none (SET) |
| `CRON_SECRET` | generated at project setup; read by Vercel Cron only | none (SET) |
| `WORKER_RUN_SECRET` | generated at project setup; sent as `X-Worker-Secret` by the scheduled worker | none (SET) |
| `NEXT_PUBLIC_API_URL`, `NEXT_PUBLIC_SITE_URL` | same-origin URLs (public by design) | none (SET) |

Optional keys that are **deliberately absent** (do not add them):
`BRAVE_SEARCH_API_KEY` (not used with `searxng`), `PROPERTY_PROVIDER`
(keeps inventory honestly empty), `WEB_SEARCH_ALLOWED_DOMAINS` (empty =
unrestricted), `WEB_SEARCH_RPM` (code default 60), `GOOGLE_MAPS_SERVER_KEY`
(requires Google Cloud billing; `MAPS_PROVIDER=none`).

## 5. Never expose (anywhere, ever)

`MONGODB_URI` (contains the password) · `SECRET_KEY` (JWT signing) ·
`GROQ_API_KEY` · `CRON_SECRET` · `WORKER_RUN_SECRET` ·
`SEARXNG_SECRET` · `SEARXNG_AUTH_TOKEN` · Vercel token · Fly token.

Rules enforced by the codebase:

* server-side only, **never** `NEXT_PUBLIC_*` (the frontend bundle is public);
* never printed by an endpoint (`/api/v1/health*` and `/api/v1/workers/status`
  return configuration **state** only);
* never committed: `vercel.env`, `backend/.env`, `frontend/.env*`,
  `infra/searxng/fly.toml.local` are all gitignored;
* the Fly container refuses to start without `SEARXNG_AUTH_TOKEN`, so a
  half-configured instance can never serve public traffic.

```

GET https://realestate-gpt-inky.vercel.app/api/v1/health           -> 200 healthy
GET https://realestate-gpt-inky.vercel.app/api/v1/health/web-search-> 200, provider=searxng,
                                                                     configured=true, enabled=true
POST https://realestate-gpt-inky.vercel.app/api/v1/search/autonomous
     "Find 2BHK apartments for rent in Hyderabad under ₹35,000"    -> web_discoveries > 0
```

Until those pass, the honest state of the site is
`PRODUCTION READY — EXTERNAL INFRASTRUCTURE CONFIGURATION REQUIRED`;
after they pass it becomes `PRODUCTION VERIFIED`.
