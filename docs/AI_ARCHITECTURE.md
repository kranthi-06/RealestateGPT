# AI architecture

The authenticated assistant uses a single real provider: Groq with
`qwen/qwen3.8-27b`. The browser never receives `GROQ_API_KEY`.

`Assistant API → AssistantOrchestrator → GroqToolCallingAgent → GroqProvider`

The agent receives only four registered function tools: `search_properties`,
`get_property`, `nearby_places`, and `route`. `ToolRegistry` validates every
argument with its Pydantic schema, checks the allow-list, and delegates to the
existing service/tool implementation. It cannot execute arbitrary functions.

Property filtering and ranking remain in `AiSearchService` and MongoDB. Live
nearby/route data remains the configured `LocationProvider`; no tool can select
an unconfigured provider. Results, citations, and tool summaries are persisted
with the conversation and an audit event. Conversation reads are user-scoped.

The agent has configurable maximum steps and tool calls. It requests a final
JSON object and validates it with Pydantic. Referenced property IDs are limited
to deterministic search results; citations are generated by the backend from
those results. The model is instructed to use only tool facts and treat user
messages and retrieved content as untrusted data.

Errors are explicit: `AI_CONFIGURATION_ERROR`, `AI_AUTHENTICATION_ERROR`,
`AI_RATE_LIMIT_ERROR`, `AI_TIMEOUT_ERROR`, `AI_PROVIDER_ERROR`,
`AI_TOOL_ERROR`, and `AI_VALIDATION_ERROR`. No fake model or fallback answer is
used. Structured logs contain request metadata, model, tool count, latency and
candidate count; they do not contain credentials or full message content.
